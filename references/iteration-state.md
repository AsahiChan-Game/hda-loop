# 制作主线、基准与连续迭代

在已有项目继续制作、研究新方法或接到方向纠正时使用。目的在于让每轮成果累积；记录保持简短，可并入项目现有任务文件。

## 最小工作记录

```text
目标与阶段：当前交付范围；Houdini 制作中 / 待看图确认 / UE 验收中等
正式主线：源 HIP/脚本、HDA 定义与当前候选、依赖
基准：参考或已认可版本/图片；认可依据；必须保持的特点
本轮：最大缺口 → 修改对象 → 预期效果 → 检查证据
变体：A/B/C 分别验证什么；对应预设
结果：改善、退步、残留问题；下一项具体行动
确认：用户批准的候选身份；无批准则如实注明
```

不复制整段聊天。首次制作记录技能版本标识或文件哈希即可；用户通知技能变更或规则冲突时读取相关更新，保留原资产进度，不因技能更新重建工程。

继续任务先核对当前文件和最近用户纠正。最新文件可能是研究样机，不能仅按时间选正式主线。旧记录与当前事实不一致时修正记录，不自动覆盖文件。

## 研究如何变成实际改进

研究前明确具体问题与完成证据；记录研究输出的路径及其用途。例如研究屋顶适配，应产出可接回当前建筑的体块到屋顶关系，而不是以另一座房子的白模替换当前成品。

研究验证后，把规则集成到正式工程，重建代表样本并比较基准，再扩展相关变体。研究失败或不适用时保留结论，继续使用有效主线。重大改架构要说明原路线的具体限制，以及如何迁移已认可构件和外观；“更通用”“更容易测试”本身不能证明值得重做。

## 检查是否退步

保留基准图片和复现条件。修改后检查受影响部分，并抽查受保护的识别特征。适合自动比较的稳定构件可比较 ID、包围盒或几何指标；视觉回归仍需看图。重采样或拓扑改变时允许合理容差，不用文件哈希相等判断美术一致。

只修局部连接时，检查其他构件未无意改变；扩展参数范围时，重跑原优秀预设；改材质或渲染时，以可比较条件区分造型与展示差别。发现退步先修或保留旧候选，不自动把新版本标成改进。

## 用户纠正后的行动

把纠正归入外观目标、功能范围、参考用途或实现方法，并更新受影响项。其余已有要求继续有效。例如“参考案例的思想”改变参考用途，不取消原风格或 HDA 制作目标。

无需重复批准已授权修复。下一步应落实到具体文件、构件或规则，并产生可检查结果；仅解释正确路线不是实施完成。需要用户作真实取舍时，保留已完成工作并给出具体冲突，避免用泛泛的“还继续吗”中断制作。
