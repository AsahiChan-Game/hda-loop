# 按尺度选择生成与验证内容

这些是设计选项与验收重点，按任务读取对应部分，不要求一次搭齐所有 HDA。

## 单体：树、草丛、灌木、藤蔓与道具

把“形态生成”和“环境散布”分开。一棵树不需要地形散布系统，一个草丛生成器不等于草地铺设工具。

| 类型 | 主要输入与控制 | 关键检查 |
|---|---|---|
| 树 | 树种/风格、尺寸、树冠引导形状、主干与枝条层级、叶簇密度、局部种子 | 主干到枝梢的渐细和连接、轮廓层次、背面、叶簇分布、根部落地 |
| 草丛 | 簇半径、高度、叶片宽度与弯曲、朝向、疏密、种子 | 基部聚合、避免刷子般均匀、近景轮廓、重复铺设后的图案和 overdraw |
| 灌木 | 引导体积、枝条结构、叶片库或叶形生成、密度与修剪形态 | 遵循体积而非填满噪声、内部结构、低密度状态仍成立 |
| 藤蔓 | 附着表面、起点/引导曲线、覆盖与排除区、增长长度、下垂、叶片间距 | 附着与转角、悬垂规律、窗门排除、无穿墙、缺失支撑面时可诊断 |
| 道具 | 尺寸、截面、样式、拼接与安装点、材质区、种子 | 功能比例、连接结构、枢轴、碰撞和实例化复用 |

暴露艺术家能理解的参数和适用范围。种子改变形态但不打破树种或设计语言；尺度改变不应让树皮或叶片失去合理比例。必要时分离轮廓、枝条、叶片的随机流，局部调整保持其他部分稳定。

输出根据需求采用 Static Mesh、packed geometry/实例或 Foliage；UV、法线、材质槽、碰撞与风权重遵循项目接口。没有风动要求时不强塞动画系统；有风动时验证 UE 材质中的真实表现及边界。叶片卡片或实体叶片依据观看距离、遮罩成本和目标平台选择。

最小有效验证：默认形态、一个明显不同的参数状态、同种子重建及一个相关边界输入；数量可按风险调整。这些是工具测试样本，不自动授权大批变体生产。检查中性照明下的几何/材质和目标场景中的最终效果。

## 建筑：外壳、所有楼层与室内物品

用户要求“里面所有东西由不同 HDA 生成”时，将它作为具体交付范围列入覆盖表：每类几何由哪个 HDA 生成、哪个 HDA 负责摆放、依赖哪些材质和预设、是否支持交互。几何生成、布局生成、复用摆放是不同能力，必须如实记录。

建议先确定一份共同的建筑布局数据，由外立面与室内共同消费；不能先随意做窗户、再独立随机房间，最后尝试对齐。

先按 [质量框架](quality-framework.md) 检查当前房屋需要的构件、空间关系和表面质量，再确定下列职责中哪些需要实现。案例用于帮助发现缺口，不决定本次房屋的风格或生成顺序。

典型职责按项目规模拆合：

- 建筑体量：占地轮廓、退界、楼层、层高、入口、屋顶与总体风格。
- 外壳与立面：墙体、开间、门窗洞口、立面模块、转角与屋顶收口。
- 室内布局：楼层、走廊、房间邻接、楼梯/电梯井、竖向管井与出入口。
- 室内构件：墙、地板、天花、门窗、踢脚线、楼梯和栏杆。
- 物品生成器：桌椅、柜架、灯具、管线、器具及要求的装饰小物；可复用同一类 HDA 的不同预设。
- 摆放生成器：根据房间用途和功能区消费物品输出，保持接地、间距、朝向和可达性。

为门扇开启、抽屉、椅子使用、玩家/AI 通行保留必要空间。结构验证应使用项目角色尺寸与容差，不把随意编造的数值当成建筑法规。楼梯需要实际连接楼层；入口要连接街道；房间需能通过约定路径到达。避免家具堵门、楼板封楼梯、外窗正对无意义隔墙等问题。

艺术家覆盖建议按 `building_id / floor_id / room_id / slot_id` 保留：锁定一个房间或家具位置后重建其他区域，不覆盖锁定项。修改布局让覆盖失去锚点时报告冲突，不悄悄把对象搬走。

验收覆盖：外观、多层平面或剖面、入口至楼上房间的实际路径、典型室内、局部尺寸变化及不同占地轮廓。先做一栋完整样本再推广；外壳通过不能代表全室内完成。门、灯和容器的交互需要 UE 行为实现及实际测试。

## 城市：道路、地块、建筑家族与流送

把城市视作分层规则与数据依赖，而非一个吞掉所有细节的巨大 HDA：

```text
城市边界 / 地形 / 保留区 / 主路约束
  → 道路网络与交叉口 → 街区 → 地块
  → 建筑类型、占地、高度、入口与风格规则
  → 建筑及室内生成 → 街道设施与植被
  → 分块烘焙、UE 分区/实例化、运行验证
```

先验证道路连通、路口与人行道衔接、地块不重叠、建筑入口可达。建筑差异来自用途、年代、街区风格、开间、屋顶和材质规则，不只缩放同一座楼。全城所有类别必须有对应生成规则或明确标记的未完成范围。

局部稳定性是核心：用稳定地块/建筑 ID 派生局部种子，不用会随排序变化的点编号作为长期身份。对拆分或合并地块建立明确的新身份和覆盖迁移策略。修改某地块只失效它及必要邻接依赖；道路大改可能合法影响多个街区，应报告影响范围。

大范围采用分块缓存与可恢复任务。缓存键包括输入、种子、HDA/规则版本、依赖库版本和相关设置；不能只看文件存在就复用。可选 TOPs/PDG 或项目现有队列，规模不需要时保持简单。设并发、超时和输出归属，避免失败后不断全城重算。

分开规划生成范围与运行时驻留范围：用户要求全室内时可以分块生成、按需加载完整室内；不能擅自用假室内材质替代。若用户接受，可另设不可进入、局部可进入和完整室内等级，但必须明确哪些楼属于哪种。

UE 的 World Partition、Data Layers、Level Instances、HLOD、Nanite 和 PCG 依据当前项目支持选择组合；并非所有 HDA 都需要 PCG，也不假定 City Sample 的旧工作流就是现代 PCG。先在一个街区验证真实输出与分区集成，再批量扩展。

城市验收需包括鸟瞰、最差街面密度、街角模块衔接、代表建筑的室内，以及一条跨分区行走/驾驶路径。检查加载卸载、碰撞连续性、重复建筑模式、驻留内存、实例/组件数量和帧时间。人群、交通 AI、破坏玩法属于额外系统，城市几何生成不代表它们已完成。
