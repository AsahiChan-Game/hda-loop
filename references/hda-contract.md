# HDA 与 UE 的可复现交付约定

## 两步状态与交接

本文件细化技术证据；正式提交仍须满足 SKILL.md 的美术自检、基准保护与三变体要求。局部研究或技术样机不能仅因以下检查通过而成为正式候选。

第一步在 Houdini 中完成 HDA 制作及所有能在 Houdini 内完成的检查：可重建源、定义/依赖、核心参数、输出数据、三个变体 A/B/C 与重复/边界检查。展示三张独立 Houdini 图和验证结果，保存交接文件身份及三个预设。状态为“Houdini 制作与自检完成，待用户看图确认；UE 未开始”。UE 特有表现与运行验证留到第二步。

用户明确确认第一步候选满意后，第二步才制作 UE 集成内容并验收：以相同预设重新生成对应的 A/B/C，等待 cook 与后处理，检查真实输出、材质、碰撞及按范围要求的 bake/PIE/性能，展示三张独立 UE 图片。完整流程需展示两组共六张图片，逐个对应；任一环境的图片不替代另一环境的图片。

用户看图确认是明确的阶段入口：记录确认消息对应的候选版本与预设；未确认前不制作 UE 材质/Blueprint/脚本/场景或运行导入/cook。自检通过、发出图片和没有回复不构成确认。针对当前候选已有的明确确认继续有效，无需重复请求。

若 UE 暴露生成器缺陷，返回 Houdini 修复并更新两组证据。改变用户已确认的形态、布局或设计时，重新展示 Houdini 三图确认；不改变可见结果的兼容性修复可沿用已有确认并记录。UE 集成配置问题在第二步修复。

## 制作前留下可检查的接口

按本次规模记录，不为简单资产搭建数据库：

| 项目 | 内容 |
|---|---|
| 身份 | HDA 定义名/命名空间/版本、源 HIP 或重建脚本、子 HDA 依赖 |
| 环境 | Houdini build、UE、Houdini Engine、所用 Labs/插件及许可证兼容性 |
| 目标规格 | 平台/设备档、实时或离线路径、观看距离/占比/重复数量、风格约定；按 [asset-standards.md](asset-standards.md) 与 [art-direction.md](art-direction.md) 选适用要求 |
| 输入 | 每个输入索引的语义、类型、是否可空、单位/坐标系及有效条件 |
| 参数 | 默认值、有效范围、单位、种子、样式/质量预设、会影响哪些输出 |
| 输出 | Mesh、实例、曲线、锚点或布局数据；稳定标识、材质、碰撞及命名 |
| 依赖 | 外部文件/材质/模块库的可解析引用、子定义位置及版本 |
| 预算 | Cook 超时、样本密度、内存/几何/组件或材质成本、运行时目标 |
| 重建 | 所有权、缓存、局部失效规则、人工覆盖、烘焙路径与替换范围 |

Houdini 与 UE 的单位及轴向转换按插件实测；用已知尺寸验证一次，不假定需手工乘 100，以免重复缩放。记录测量容差和实例变换处理。

复杂生成器区分 Preview 与 Final 质量，使艺术家编辑时有响应；质量切换不应改变已锁定的布局和身份。缺失必需输入时返回具体错误，不悄悄用默认资产冒充成功。允许空结果的条件应明确。

预算各项标识项目约定、估算或实测。第一步可在 Houdini 检查几何、UV/属性、依赖、材质预览与 cook 成本；UE 实际压缩/驻留、着色、碰撞、LOD/流送以及设备性能必须在用户看图确认后的第二步验证。Houdini 的材质预览不证明最终 UE shader 风格一致。

## 第一步：源与依赖

参数必须驱动可编辑的生成网络。禁止用单个固定 mesh 加无效滑条充当生成器。保留已验证母模与复用模块；HDA 承担组合时如实标识为组合工具。

测试 HDA 在新的 Houdini 会话中加载和 cook，确认没有仅存在于当前会话的子定义、绝对临时路径或未声明文件依赖。按许可证允许的资产格式保存，不靠重命名扩展名解决兼容问题。仅在引入或分发资源时检查相应许可，不扩大到无关资产库。

## 第二步：UE 执行链

优先项目已有脚本与文档化 API。HOM/hython 用于 Houdini 构建；需要 Engine 会话时使用实际可用的 HAPI/SessionSync；UE 内采用已安装版本支持的 Houdini Engine Public API 或项目工具。不要凭空假设方法名或安装新桥接服务。

```text
第一步已完成的 HDA / 定义 / 依赖 / A/B/C 预设
  → UE 导入 / 有效 Engine 会话
  → 实例化完成
  → cook 完成 / 输出后处理完成
  → 检查实际对象和组件
  → 参数变化后 recook / 幂等性检查
  → 需要时 bake、保存、重新打开
  → PIE / 性能 / 打包（按交付范围）
```

异步调用返回不能代表完成。使用该版本公开的完成通知或同步接口，配合超时和失败出口；在输出后处理完成前不读取结果，不并发改动同一个实例。检查真实输出组件的尺寸、数量、类型、材质和碰撞，不能拿 HDA 外层 Actor 的包围盒代替。

实例化路线区分 packed geometry、现有 UE 资源引用、Foliage 和需要独立行为的 Actor。具体属性的名称、类型和 owner class 查已安装版本官方文档；不要无条件强制 HISM，尤其要结合 Nanite 与实测选择。

Cook、rebuild 和 bake 是不同操作：更新参数通常 recook；定义发生变化时按版本接口重新加载/rebuild；bake 创建脱离生成器连接的 UE 产物。需要 bake 的交付应验证烘焙对象重新打开后仍有正确资源引用，没有意外依赖临时 cook 对象。正式运行产物按项目要求验证，不为测试擅自卸载插件。

## 最小有意义验证

按实际风险选案例，不要求测试所有参数组合：

- 三个用于最终截图的有效变体，覆盖能证明核心生成能力的参数、种子或输入变化；其中可包含默认状态。
- 相同输入/版本/种子重建，比较稳定的几何或布局指标；允许数值容差，不要求二进制文件逐字节相同。
- 一个主要边界输入或不合法输入，确认报错、夹取或空结果符合约定。
- UE 中参数变化、输出更新和重复 cook 没有累计重复 Actor/实例。
- 组合工具验证子 HDA 依赖；建筑验证空间连通；城市验证局部更新与缓存失效。
- 交付需要烘焙时验证 bake 和重新加载；声称可玩时走实际通路；声称可分发时运行相应打包检查。

生成输出带本次归属标识；替换和清理仅限本次明确拥有的对象。保留用户改动、地图及外部 Actor 状态。不要直接改写二进制 `.uasset`/`.umap`，使用 UE 支持的编辑途径。

## 交付记录

记录输入、参数、种子、版本、操作/脚本入口、输出路径、实测值和截图路径。区分原始几何三角数与实例化后的数量，也区分 cook 时间和帧时间。视觉图片需真实打开检查。

六张最终变体图按 `variant_id → 输入/预设 → Houdini 输出与图片 → UE 输出与图片` 建立对应记录。记录共同使用的最终 HDA 路径、SHA-256、资产定义名和依赖版本；A/B/C 之间参数与输入可以不同，但同一变体跨环境预设一致，输入转换差异需声明。若重新修改 HDA，重新生成或验证三个最终变体，并更新两组共六张图片与记录，不混用旧版输出。可以补充诊断视角，但它们不代替每个环境各三个不同变体的交付图。

报告中分别标识已完成、部分完成、失败、未验证及不适用。静态脚本检查不能标记为 Houdini cook 通过；Houdini 成功不能标记为 UE 成功；UE 编辑器成功不能标记为 PIE/打包成功；自动视觉评审不能标记为用户美术批准。
