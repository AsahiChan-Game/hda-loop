# 数字资产质量与缺口判断

目标是从具体任务推导制作条件。以下八项是检查视角，按对象取舍；不是必须拆成八个模块，也不是让用户先填一张大表才能开始。

开始时结合 [平台与资产标准](asset-standards.md) 选择实际用途和成本要求，并用 [美术方向](art-direction.md) 明确风格的可检查条件。每项缺口须在这些条件下判断：手游与影视不共用固定预算，写实与卡通不按同一细节密度评分。

## 八项必要条件

| 条件 | 核心判断 | 房屋示例 | 树或道具示例 |
|---|---|---|---|
| 设计目标 | 什么特征决定身份与品质？用途和观看条件是什么？ | 建筑用途、风格、体量比例、可进入范围 | 树种与树冠轮廓；道具用途与功能比例 |
| 基础构件 | 需要哪些可用内容，其本身是否合格？ | 门窗、楼梯、屋顶与其他构件 | 枝叶、树皮；零件、接口与表面 |
| 整体结构 | 主次、比例和空间组织是否成立？ | 体量、屋顶、楼层与入口 | 主干/分枝层级；主体与附属部件 |
| 构件关系 | 如何连接、对齐、避让和支持？ | 门洞匹配门框，楼梯连接楼层 | 枝干连接、叶片附着；零件安装位置 |
| 可控变化 | 哪些可变、哪些固定，变化后仍是什么？ | 建筑布局/样式变化仍保持风格和可达性 | 树形变化仍属于同一树种；道具尺寸变化不破坏功能 |
| 表面表现 | 几何、UV、材质和细节是否协调？ | 接缝、纹理尺度、边缘与合理变化 | 叶片朝向和透光；材质区和磨损依据 |
| 使用与环境 | 如何落地、安装、接触或被使用？ | 入口、家具净空、场地与碰撞 | 根部落地、藤蔓附着；枢轴、握持或安装点 |
| 工具与验证 | 能否可靠控制、重建并满足目标平台？ | 参数、依赖、UE 输出及代表规模性能 | 关键变化、重复使用成本和异常输入反馈 |

## 从条件得到本轮工作

根据现有证据写一个简短缺口记录，只保留会影响当前制作的条目：

`质量目标 → 已有证据 → 缺口或待确认项 → 制作/检查动作 → 通过条件`

例如：门窗需要随层高变化正确安装；已有门框模型，但还没验证尺寸约定；先量尺寸和锚点、检查开口对应关系，再决定是否改模型或组合规则。不能仅因为有模型文件就认定可用，也不能在检查前直接重做。

行动可以是复用、检查、补充参考、制作模块、建立规则或验证环境。未知能力标为待验证，避免凭猜测扩展任务。只向用户询问会改变目标、关键判断或授权范围的缺失信息。

## 两条独立验收线

**成品线**：一个具体结果在声明的观看和使用条件下，整体、细部、材质、空间与性能都达到目标。

**生成器线**：核心输入在声明范围内变化后，仍能输出合格结果；同输入可复现，关键约束和锁定项被保留，无效输入有明确反馈。

单件交付按单件要求验收；用户要生成器时，两条线都需要证据。用几个代表性变化检查生成器，不能用无限随机抽样替代规则，也不能从少量测试宣称任何输入都可靠。

## 质量问题的归因

| 症状 | 优先检查 | 避免的无效行动 |
|---|---|---|
| 整体不好看 | 设计目标、轮廓、比例与视觉主次 | 先堆装饰或提高面数 |
| 单个部件明显粗糙 | 模块质量、表面与材质 | 试图通过散布数量掩盖 |
| 接缝、悬空、穿插 | 尺度、锚点、连接和排除关系 | 只手动修一个种子结果 |
| 变体雷同或混乱 | 分层变化范围、风格约束与稳定项 | 对所有部件加独立噪声 |
| 只能拍一个角度 | 缺失几何、多视角设计及材质 | 继续调镜头隐藏缺陷 |
| 看起来对但不能用 | 碰撞、净空、交互和实际输出 | 用截图作为功能证据 |
| 规模一大就失效 | 实例化、组件、遮罩、内存、cook 与流送 | 仅减少面数或直接套某项引擎技术 |

这些是诊断方向，不是已证实的根因；检查后选择改动。

## 怎样使用案例

湖滨小屋、Titan、City Sample 可以帮助识别构件、关系、控制和验证需求，也可以显示一个方案遗漏了哪些层次。案例来源与观察范围见 [sources.md](sources.md)。

提炼方式为 **观察到的证据 → 对质量条件的启发 → 在当前资产上是否适用**。不要从一个案例推出所有资产都必须使用它的材质、风格、模块拆分、软件版本或节点实现。完整课程没有检查过时，不声称知道其具体网络；案例没有展示某种能力时，也不据此断言它一定没有。
